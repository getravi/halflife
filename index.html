On what this plan is and isn't. This plan focuses on the Applied Research & Agentic Evaluation track, omitting low-level custom GPU kernels to focus on model scaling intuition, fine-tuning (LoRA), data quality, and rigorous scientific evaluations. The 44-week curriculum (10-15h/week commitment) is designed to produce reproducible public artifacts and credible interview evidence. Start by sharpening your coding velocity in Phase 0, then progress sequentially.

Phase 00 · Weeks 1–10

Programming
foundations

This phase assumes you are starting from close to zero. You will learn Python properly, then array thinking, then the math that deep learning is actually made of. Nothing here is optional and nothing here is skippable — every later phase silently assumes all of it. Target 10–15 hours/week over 10 weeks.

0% complete
Start here, today. Install Python 3.13 and uv before anything else, then work Task 01 in order. If you already write Python daily and know what a decorator and a generator are, skim Task 01 for the exit check and start at Task 02 instead.
Task 01 Python from zero Exercise
Set up and write your first programs
Install Python 3.13 and Astral's `uv`. Create your first project with `uv init`, run scripts, use the REPL. Learn variables, numbers, strings, f-strings, and `print` debugging. Write 20 tiny programs — no tutorials on autopilot, type every line.
Week 1
Python Tutorial ↗
Data structures and control flow
Lists, dicts, sets, tuples. `if`/`for`/`while`, slicing, iteration, nesting. Learn what mutability means and why it bites. Build: a word-frequency counter, a to-do list, and a text-file parser — from a blank file, not from a template.
Week 2
Functions, files, errors, and classes
Function arguments and return values, scope, exceptions and `try`/`except`, reading and writing files, modules and imports, and basic classes with `__init__`. Learn to read a traceback top-to-bottom and fix the actual line it names.
Week 3
Exit check
From an empty file, write a program that reads a text file, counts word frequencies, sorts by count, and writes the top 20 to a new file — with a function per step and error handling for a missing file. No copying, no AI assistance. If it takes over an hour, repeat Week 2.
Week 3
Do not use an AI assistant to write code in this phase. It will produce working programs and leave you unable to debug a shape mismatch in Phase 1. Use it to explain concepts, never to emit code you then paste.
Task 02 Python fluency refresh Exercise
Refresh core Python
List/dict/set comprehensions, generators, decorators, context managers, *args/**kwargs. Write code by hand. Use Python docs directly. Focus on coding speed.
Week 4
docs.python.org ↗
Type annotations & tooling
Set up a clean environment with ruff 0.16 and mypy 2.x. Practice using explicit type hints throughout. Strong typing and linting habits make larger ML/evals codebases easier to review. Astral's `ty` is the fast Rust type checker to watch, but it is still 0.0.x — do not make it your default yet.
Week 4
Exit check
Write a generic typed LRU cache from scratch using only Python stdlib (no functools). If you can do it cleanly in under 30 minutes, you're done.
Week 5
Focus on coding hygiene. Mypy type-checking and Ruff linting should run on save in your VS Code workspace. Build this reflex on day one.
Task 03 NumPy array thinking Exercise
Think in arrays, not loops
Work through the NumPy 100 exercises. Focus on broadcasting, fancy indexing, einsum, and axis semantics. Absolutely no Python for-loops on arrays.
Week 6
numpy-100 ↗
Matrix ops by hand
Implement matrix multiply, softmax, and layer norm from scratch with NumPy. Verify outputs against reference implementations. JAX/PyTorch APIs are very similar.
Week 6
Exit check
Implement scaled dot-product attention (Q, K, V → output) using only np.einsum and np.exp. No loops. Must match PyTorch reference to 1e-5 tolerance.
Week 6
Array thinking is non-negotiable. Both PyTorch and JAX require thinking in terms of high-dimensional array transforms. If this isn't fluent, model building is painful.
Task 04 Algorithms & complexity Theory
Complexity intuition
Read code loops and state time/space complexity instantly. Focus on: sorting, tree traversal, BFS/DFS, sliding window, two-pointer patterns.
Week 7
neetcode.io ↗
Optimizer math & 5 LeetCode
Implement SGD, SGD with momentum, and Adam from scratch in NumPy — derive each update rule on paper first. Verify Adam matches torch.optim.Adam output. Then solve 5 Medium LeetCode problems (arrays + hashmaps only) for baseline debugging confidence. Stop at 5.
Week 7
Ruder: Optimizer Overview ↗
The optimizer math is the deliverable, not LeetCode. You will use Adam in every training loop from Phase 1 onward. Understanding its update rule on paper is directly useful. LeetCode is capped at 5 problems — it's for debugging speed only. Do not expand it.
Task 05 Git & dev environment Exercise
Git fluency
Master: interactive rebase, cherry-pick, bisect, stashing, worktrees, and resolving merge conflicts. Run a git bisect on a buggy repo history.
Week 8
Workspace setup with 'uv'
Set up a private learning repo. Configure python management using Astral's `uv` (faster and cleaner than conda). Set up VS Code and Google Colab.
Week 8
astral-sh/uv ↗
Profiling scripts
Learn `cProfile` and `line_profiler`. Profile a bottlenecked Python loop. Identify slow calls and optimize them. This builds optimization reflexes.
Week 8
Task 06 Math refresh Theory
Linear algebra warmup
Eigendecomposition, SVD, matrix rank, projections. Work 10 problems by hand. Essential for low-rank adjustments (like LoRA) in Phase 3.
Week 9
3Blue1Brown ↗
Calculus & MLP Backprop
Chain rule in vector form, Jacobians, Hessians. Derive backpropagation for a 2-layer MLP by hand. Verify the gradients numerically in NumPy.
Weeks 12–13
Probability & Entropy
Cross-entropy, KL divergence, entropy. Derive the softmax gradient by hand. Understand the mathematical justification for Cross-Entropy loss.
Week 10
Do not skip Day 1. Do not skip pencil-and-paper work. Understanding matrix dimensions during backpropagation is key to debugging neural network shapes later.

Phase 02 · Weeks 23–34

JAX, TPUs &
Scaling Laws

Transition to JAX's functional programming paradigm and learn compute-scaling economics at toy scale. Learn to shard computations across accelerators when available, complete Scaling Book exercises, and replicate small loss-vs-compute curves with rigorous methodology.

0% complete
JAX's paradigm is purely functional. It maps mathematical models directly into optimized XLA graphs. But it requires you to manage state explicitly (no side effects). Keep this in mind as you learn the ecosystem.
Week 15 Goal (JAX Week 1): Write a training loop with jit/vmap/grad without looking anything up. Understand why each transform exists, not just how to call it.
Day 01 JAX is not NumPy with autodiff Concept
Pure functions only
Read "Thinking in JAX." JAX transforms require pure functions — no side effects, no in-place mutation, no Python state. This isn't a style preference; it's how tracing works.
~2h reading
docs.jax.dev ↗
Tracing model
When jit runs, it traces with abstract values. Understand what "abstract" means: this is why Python conditionals on traced values fail at trace time, not runtime.
~1h
Cause the failure modes
Run these deliberately: leaked tracer error, in-place mutation silently doing nothing, Python if on a traced bool. Know the error messages before they surprise you in week 2.
~1h
Do not skip Day 1. Most JAX confusion in weeks 2–4 of the broader plan traces back to not internalizing purity here.
Day 02 grad — automatic differentiation Code
jax.grad basics
grad wraps a scalar-output function and returns a gradient function. Work through: grad of simple functions, grad of loss over parameters, value_and_grad for efficiency.
~1.5h
jacfwd vs jacrev
Forward mode (jacfwd) is efficient for wide Jacobians. Reverse mode (jacrev/grad) for narrow outputs. Understand the tradeoff — it comes up in kernel work later.
~1h
Higher-order grads
grad(grad(f)) just works in JAX. Build a Hessian. This is where JAX's composability visibly beats PyTorch's autograd model.
~1h
Day 03 jit — compilation and recompilation Code
When jit recompiles
jit caches keyed on input shapes and dtypes. Shape change = recompile. Python values as arguments = recompile every call unless marked static_argnums. Know this cold.
~1.5h
Debugging inside jit
Python prints run at trace time, not runtime. Use jax.debug.print for runtime values, jax.debug.breakpoint for stepping. Practice with a real example.
~1h
Benchmark jit speedup
Use jax.block_until_ready() for accurate timing — JAX is async. Measure separately: first call (compile + run), second call (run only). The delta is compile cost.
~1h
Day 04 vmap — vectorization without loops Code
vmap mental model
vmap transforms a single-example function into a batched one. It vectorizes, not parallelizes. No extra memory copies, no Python loop overhead. in_axes controls which args get batched.
~1.5h
Practical vmap uses
Per-example gradients (vmap(grad(loss))) is the canonical pattern. Also: batched matrix ops, pairwise distances without broadcasting confusion. Build all three.
~1.5h
Composing transforms
jit(vmap(grad(f))) is the standard training pattern. Order matters: jit outermost = one compiled artifact. vmap outermost = vectorize then compile. Try both, measure both.
~1h
Day 05 First training loop — logistic regression Integrate
Manual training loop (no libraries)
params as pytrees, loss function, grad step, jitted update. No Flax, no Optax. This forces understanding of what those libraries abstract. End target: working MNIST MLP.
~2h
Pytrees deep dive
Pytrees are JAX's nested container abstraction. Every parameter dict is a pytree. Master tree_map, tree_leaves, tree_flatten — they're used everywhere in JAX code.
~1.5h
PRNG key management
JAX has explicit PRNG — split keys before every random call. Reusing a key gives the same result silently (no error). This catches people constantly. Practice the split pattern.
~1h
JAX week 1 exit check: Write a 2-layer MLP for MNIST using only jnp + grad + jit (no Flax). If you can do it without googling, you are done.
JAX week 2 goal: Use Flax NNX + Optax fluently, write a scan-based training loop, and run your code across multiple devices with explicit sharding. Know when sharding beats vmap.
Day 06 Flax + Optax — the standard stack Code
Flax NNX (current API)
Flax NNX is the recommended API for new code — stateful modules with explicit variable management. Linen is older and functional; it is not deprecated (the Flax team still supports it because most existing code depends on it), so you will keep meeting it in papers and repos. Write NNX, read Linen.
~1.5h
Flax NNX docs ↗
Rebuild your MLP with Flax + Optax
Take the week-1 manual training loop and rebuild it with Flax and Optax Adam. The contrast reveals exactly what those libraries are doing — which is the point.
~2h
Optax transform chains
Optax is functional: optimizers are stateless transforms on gradients. chain(clip_by_global_norm(1.0), adam(lr)) is the standard transformer training pattern. Build a custom optimizer chain.
~1h
Day 07 scan and lax control flow Code
lax.scan mental model
A Python for-loop inside jit unrolls — N iterations = N copies of the compiled graph. scan compiles one iteration and loops in XLA. Essential for long sequences and the scaling book exercises.
~1.5h
scan-based training loop
Rewrite your Flax training loop using lax.scan. carry = (params, opt_state), xs = batch indices. Accumulate metrics in ys. This exact pattern appears throughout the scaling book.
~2h
lax.cond and while_loop
Python if inside jit = static branch (trace time). lax.cond = dynamic branch (both branches must have same output shape). while_loop = dynamic iteration. Build a working example of each.
~1h
scan is not optional. The scaling book uses it extensively. If scan is uncomfortable after day 7, repeat the training loop exercise before moving to Day 8.
Day 08 Parallelism: explicit sharding Code
Explicit sharding (the current default)
Since JAX 0.9.0, `jax.make_mesh` creates meshes with `AxisType.Explicit` by default — JAX propagates shardings through the type system and errors on ambiguous communication instead of silently inserting it. Build a mesh with `jax.make_mesh`, activate it with `jax.set_mesh(mesh)`, annotate tensors with `jax.P` (the top-level alias for PartitionSpec), and write a sharded training step: replicate params, shard the batch along the data axis. Note `with mesh:` is deprecated — use `with jax.set_mesh(mesh):`.
~2h
Explicit sharding ↗
Collective ops (pmean, psum)
After each device computes gradients, average them with lax.psum / lax.pmean — this is AllReduce. Understanding it is prerequisite for all distributed training work, and it is what every parallelism strategy in the scaling book ultimately reduces to.
~1.5h
shard_map for manual control
`jax.shard_map` is the manual mode: you write the per-device program yourself and place the collectives by hand. Use the top-level `jax.shard_map`, not the old `jax.experimental.shard_map` import. One gotcha since 0.9.1: in Explicit mode, shard_map asserts your input PartitionSpec matches `in_specs` rather than silently resharding — call `jax.reshard` first if they differ.
~1.5h
shard_map guide ↗
Do not learn pmap. JAX 0.10.0 removed the C++ pmap infrastructure; `jax.pmap` survives only as a thin wrapper over `jit(shard_map)` and `PmapSharding`, `device_put_sharded`, and `device_put_replicated` now raise AttributeError. Any tutorial, blog post, or scaling-book snippet built on pmap predates this. Read it to recognise it, translate it mentally to sharding, and never write it.
Day 09 TPU basics without a budget Integrate
Accelerator setup
Colab no longer hands out TPU v2-8 slices, so use Kaggle — still free TPUs, and the option the scaling book itself now points readers to. Failing that, rent an 8-core GCP slice, or set `jax.config.update("jax_num_cpu_devices", 8)` to fake eight devices on your laptop, which is enough for every sharding and shard_map exercise here and costs nothing. Verify `jax.devices()` first, record the hardware, keep it reproducible.
~30 min setup
GPU vs TPU differences
TPUs prefer bfloat16. No float64. Matrix dims should be multiples of 128 for peak utilization. XLA uses tile-based execution — understand why padding to 128 matters for throughput.
~1.5h
Port your MLP to all 8 devices
Take your Flax training loop and run it across all available devices with explicit sharding. Replicate params, shard the batch, average gradients with pmean, and report throughput honestly for your hardware — including the case where "your hardware" is eight fake CPU devices.
~2h
Day 10 Transformer block + profiling setup Integrate
Transformer block from scratch
Multi-head self-attention, MLP sublayer, layer norm, residual connections — in Flax NNX. No copying from examples. This is the direct prerequisite for the Phase 1 10M transformer exercise.
~3h
Basic JAX profiling
jax.profiler + TensorBoard. Learn to read a trace: what's XLA compilation vs execution, where is time spent. This is the entry point to roofline analysis in Phase 2.
~1.5h
Start the scaling book
Don't wait. Open the book today and do the first 2–3 exercises. The mental model (tokens, parameters, compute budget) should run in parallel with code work from here on.
~1.5h
jax-ml.github.io/scaling-book ↗

0% complete
Agent evaluation is a science. Avoid simple vibe checks or manual prompt adjustments. State your hypothesis, control variables, dataset boundaries, baseline models, uncertainty estimates, and systematically classify failure modes.
Environments are the 2026 unit of work. Anthropic is hiring research engineers for "Universes" to build agentic environments; OpenAI posts for "Frontier Evals and Environments"; Meta's evals roles name benchmarks and RL environments in the same sentence. The research agrees — the flagship 2026 agentic-RL result scaled environments, not algorithms. If you ship one thing from this plan, ship an environment with honest reliability numbers attached.

Task 02 RL with verifiable rewards Exercise
Run a GRPO-family training loop
Use TRL's GRPO trainer on a small verifiable task — arithmetic, or anything with a programmatic checker. Weeks 38–39
huggingface/trl ↗
Read the RLVR debate honestly
This is contested ground and knowing that is the point. Read arXiv 2504.13837 (base models win at large k — does RLVR add capability at all?), then 2506.10947 (Spurious Rewards — random rewards produce large gains on Qwen but not Llama or OLMo), then 2505.24864 (ProRL — prolonged RL does expand the boundary), then 2510.04028, which reconciles them: early training exploits and narrows, prolonged training explores and expands. The two camps were measuring different phases.
Week 39
arxiv 2510.04028 ↗
Learn what actually moves the number
Read arXiv 2510.13786, The Art of Scaling RL Compute (400k+ GPU-hours), which finds sigmoidal rather than power-law curves — design choices buy compute efficiency, not a higher asymptote. The practical lesson: do not spend this phase collecting GRPO variants. Pick one, scale it, and measure. Then read the RLHF Book and its companion lecture course, currently the best free post-training curriculum available.
Week 40
RLHF Book course ↗
On-policy distillation is the 2026 recipe. The current accepted pipeline is SFT-distill for a cold start, then RLVR, then on-policy distillation as a compaction step — reported at roughly a tenth of the GPU-hours of RL alone for comparable reasoning scores. Know the shape of this pipeline even if you only ever run the first two stages yourself.
Task 03 Evaluations & environments Agents
Survey evaluation tooling
Before building custom, audit the ecosystem: run lm-evaluation-harness on MMLU or GSM8K (understand task abstraction, few-shot handling, normalization). Design Controlled Experiment
Task selection is the hardest judgment call — do this before any code. Good criteria: (1) objectively verifiable answers without an LLM judge; (2) meaningful variance across models — not trivially solved or impossible; (3) narrow enough to diagnose specific failure types. Good examples: multi-step arithmetic with hidden state, code generation with execution verification, structured extraction with known ground truth. Then define: baselines, metrics, leakage checks, rubric, ablation variables — before running anything.

Reasoning, reward models & what replaced PRMs
Read 'Let's Verify Step by Step' (Lightman et al.) for process vs outcome reward models, then DeepSeek R1 — which is the citable inflection point where PRMs lost for math credit assignment, abandoned for rule-based outcome rewards over training overhead and reward hacking. PRMs were repositioned, not killed: what survived is generative step-level critique (arXiv 2501.07301).
